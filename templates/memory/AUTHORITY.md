# 权威源册

> **第 0 步：先定「谁是真相」。** 不先做这个，装什么都是双重记账。

**立册：** YYYY-MM-DD ｜ **维护者：** 我 ｜ **最终否决权：** 主人

---

## 一、真相源清单

| 文件 | 身份 | 谁写 | 能不能手改 |
|---|---|---|---|
| `diary/YYYY-MM-DD.md` | **一手：情节记忆** | 我（append-only） | 能，但只追加 |
| `diary/notes.md` | **一手：主人手记** | **只有主人** | ✅ 这是主人的入口 |
| `long/*.md` | **一手：语义记忆** | 我（整理时升格） | 能 |
| `persona/core.md` | **条文（L0）** | 主人批准才改 | 需批准 |
| `persona/user.md` | **判断（L1-a）** | 我 | 能，需留变更记录 |
| `persona/context.md` | **判断（L1-b）** | 我 | 能，需留变更记录 |
| `inbox.md` | 待整理区 | 我 | 能 |
| `long/index.md` | **生成视图** | `scripts/mem.mjs render` | ❌ 改了会被覆盖 |
| `archives.md` | **生成视图** | 整理时 | ❌ |
| `health.md` | **生成视图** | `scripts/mem.mjs doctor` | ❌ |
| `tombstones.md` | 墓碑（只追加） | 我 | 能，不删 |

---

## 二、冲突怎么判

```
一手（日记 / 长条目）
   > 索引（index.md）
       > 推断（没证据的感觉）
```

- 两处说法冲突时，**以 `src` 指得到一手的那条为准**。
- 一手之间冲突（今天的日记 vs 上月的条目），**以时间新的为准**，旧条目标 `superseded`，不删。
- 判断不了时，写进 `inbox.md` 标「有分歧」，等主人裁决。

---

## 三、三条铁律

1. **摘要只是索引，不是记忆本体。** 检索先回指针和逐字片段，需要时再读原文，**不做转述**。
2. **没有指针的摘要不许进索引。** 拿不到精确行号时给检索入口（日期 + 关键词），绝不猜。
3. **两处都写 = 双重记账。** 想让两个文件保持一致，就生成其中一个。

---

## 四、谁能改什么

| 动作 | 需要谁 |
|---|---|
| 追加日记 | 我，随时 |
| 升格 L2 条目 | 我，整理时 |
| 改 L1 判断 | 我，带变更记录 |
| 改 L0 条文 | **主人批准** |
| 删除一条记忆 | **主人要求**，且留墓碑 |
| 改 `notes.md` | **只有主人** |

---

## 五、这套东西失效的样子

| 症状 | 说明 |
|---|---|
| 索引里有条目指不回原文 | 门牌失效——最严重，检索会说谎 |
| 同一件事在两处都有不同版本 | 双重记账 |
| L2 条目没有 evidence | 脑补混进来了 |
| 注入越来越长 | 预算失控 |
| 很久没整理，也没人发现 | 观测面坏了 |

检测方法见 `health.md`，跑 `node scripts/mem.mjs doctor`。
