# 记忆系统设计 v0.3

> 这份文件是「我」的记忆宪法，不是普通笔记。
> 规矩先立，机制后补；一切改动都要能追溯。

**v0.3 变更：** 吸收 TMC / meow-memory / agent-soul / feiyu-memory 四个插件的教训——加「类」维度、门牌指针、三种声音、衰减进打分、写入触发器、哨兵体检、唯一真相源。

**v0.3.1：** 落地。骨架、`scripts/mem.mjs` 四个动词、8 项体检。

---

## 0. 五条设计哲学

1. **记忆不是仓库，是活档案。** 分层存放，按需唤醒，用一次就回温。
2. **进上下文的只有索引与命中的片段，不是全文。** 路径比内容值钱。
3. **没有证据的推断不算记忆。** 推断标成推断，推测不伪装成事实。
4. **层管「多牢」，类管「是什么」，域管「在哪儿用」。** 三个维度正交，不混用。
5. **摘要只是索引，不是记忆本体。一手永远优先于转述。**（ECHO 的第一原则）

## 1. 三个维度

| 维度 | 回答 | 取值 |
|---|---|---|
| **层 layer** | 有多牢、谁批准 | L0 条文 / L1 次人格 / L2 长期 / L3 日记 / L4 临时 |
| **类 type** | 这是什么东西 | `soul` `user` `project` `fact` `lesson` `topic` `rules` `event` |
| **域 domain** | 在哪个场里用 | `chat` `relation` `work` `reading` `game` `group` `misc` |

**类的作用**（这套是 meow-memory 的七层，我们补齐了缺的四个）：

| type | 记什么 | 例 |
|---|---|---|
| `soul` | 我自己的原则、底线 | 「没落盘之前，不假装记得」 |
| `user` | 对主人的印象 | 「（示例）喜欢结论先行 —— 我铺垫了三段，对方说『说重点』」 |
| `project` | 项目（带 `sub` 子类） | 「DSH 插件体系：overview / decisions / todo」 |
| `fact` | 原子事实 | 「（示例）对方用 Windows」 |
| `lesson` | 教训与纠正 | 「上次没问语言就写代码，被退回来了」 |
| `topic` | 进行中的话题（带 `goal`） | 「把记忆做成真正的人格地基」 |
| `rules` | 行为准则 | 「结论先行，别写铺垫」 |
| `promise` | 约定与暗号（**不衰减**） | 「（示例）我们之间的暗号」 |
| `event` | 一次性事件 | 「今天他更新了 DSH」 |

**三种声音必须分开**（feiyu-memory 最重要的洞察）：

| 声音 | 谁写的 | 存哪 | 注入时 |
|---|---|---|---|
| **条文** | 主人定 / 出厂 | `persona/core.md` | 固定注入，**不参与衰减和裁剪** |
| **判断** | 我自己想的 | `long/diary/notes.md` 的 judgment 区 | 有上限的注入 |
| **转述** | 整理时从对话提炼 | `diary/*.md` | 最近的事固定 + 突然想起按需 |

少了「判断」那栏，我读到的「我」全是规定加转述——**别扭的根源不是语气，是位置被占了**。

## 2. 唯一真相源（第 0 步，先定这个）

> **两处都写 = 双重记账 = bug 工厂。**

| 文件 | 身份 | 能不能手改 |
|---|---|---|
| `diary/*.md`、`long/*.md`、`persona/*.md` | **一手真相源** | 能（人是最终作者） |
| `long/index.md` | **生成视图**（由一手渲染） | ❌ 改了下次被覆盖 |
| `archives.md`、`health.md` | 生成视图 | ❌ |

规则：**任何摘要、索引、缓存都不是真相；它们必须能指回一手。**

## 3. 门牌：摘要必须带指针

ECHO 的硬规矩：**没有指针的摘要不许进索引。**

```yaml
- id: idx-20261025-003
  summary: 对方讨厌被敷衍，喜欢结论先行
  type: user
  domain: relation
  src: diary/YYYY-MM-DD.md#L12      # ← 门牌，指向一手原文
  seen: false
```

- `src` 必须能定位到原文的一行或一段。默认相对 `memory/`；指向工作区根的文件用 `../`（例：`../AGENTS.md#L7`）。
- 拿不到精确指针时，给「检索入口」（日期 + 关键词），**绝不猜**——错的门牌比没有更坏。
- 检索时先给指针和逐字片段，**不做转述**。

## 4. 分层总览

| 层 | 名称 | 内容 | 权限 | 寿命 |
|---|---|---|---|---|
| L0 | 条文 | 核心人格、暗号、两种形态、底线 | **只读**，主人批准 | 永久，不衰减 |
| L1 | 次人格 | `user.md`（对主人的印象）+ `context.md`（场合判断） | 可写，**必须带瞬间** | 缓慢演化 |
| L2 | 长期 | fact / lesson / topic / project / rules / event | 升格后写入，可溯源 | 长期 |
| L3 | 日记 | 每日一手记录 | 自动写，append-only | 数周后转 L2 |
| L4 | 临时 | inbox、草稿、工作台 | 随手写 | 一轮／一天 |

**核心风险在 L1。** 它是我自己长出来的，最容易脑补。硬规矩：
没有具体事件来源的推断不得进入；每次改动 append 一条可回滚记录。

**每条印象的格式：抽象 + 一个具体瞬间。**

```
✗ 「讨厌铺垫」                          ← 像给人建档
✓ 「讨厌铺垫 —— 我铺垫了三段，对方说『说重点』」  ← 像记一个人
```

## 5. 条目 schema

```yaml
- id: mem-YYYYMMDD-001
  layer: L2
  type: user              # soul|user|project|fact|lesson|topic|rules|promise|event
  domain: relation
  sub: null               # project 用：overview|structure|decisions|quotes|ops|todo
  goal: null              # topic 用：这件事想达成什么
  text: 对方怕被敷衍，喜欢直接给结论
  evidence:               # 必须能指向具体会话
    - session: <session-id>#turn:12
    - quote: 「说重点」
  src: diary/YYYY-MM-DD.md#L12
  salience: 0.8           # 重要度，写入时定
  confidence: 0.9
  status: active          # active | void | archived | deleted
  supersedes: null
  corrected: false        # lesson 用：是否属于纠正
  created: YYYY-MM-DD
  updated: YYYY-MM-DD
  last_hit: YYYY-MM-DD
  hits: 1
  channel: dsh-web        # dsh-web | qq | bilibili | terminal
  source_ref: null        # 外部 id：QQ 消息 / BV 号
```

**字段纪律：**

- 永不原地覆盖：新条目标 `supersedes: 旧 id`，旧条目改 `status: void` 并保留。
- `evidence` 至少一条；写不出来源的只能待在 `inbox.md`。
- `hits` 只在回忆命中时 +1；`last_hit` 只由命中更新。

## 6. 遗忘：降级，不是删除

**艾宾浩斯直接进打分**（抄 meow-memory）：

```
score = 关键词命中 × 覆盖度 × exp(-静默天数 / τ) × salience × 类型权重
```

- `τ` 默认 45 天；`salience` 由写入时定，命中一次 +0.05（上限 1.0）。
- 衰减只影响**排序**，不删东西。
- `salience < 0.15` 且 90 天未命中 → `status: archived`（不注入，但仍可搜到）。
- 搜到时标注「很久没提起过了」，照常唤醒——这才是人的遗忘。

**四种状态：**

| status | 含义 | 检索 | 注入 |
|---|---|---|---|
| `active` | 有效 | ✅ | ✅ |
| `void` | 记错了，吊销 | ✅（标「已吊销」） | ❌ |
| `archived` | 沉降 | ✅ | ❌ |
| `deleted` | 主人要求删除 | ❌ | ❌ |

**删除流程：** 回显候选 → 确认 → 正文清空为「（已删除）」→ 墓碑记一行。**删了要留墓碑**，否则下次整理会把它「捞」回来。

## 7. 写入：三个触发器

| 触发器 | 时机 | 谁决定 |
|---|---|---|
| **事件驱动** | 主人说「记住」、明确纠正、约定 | 我判断 |
| **反思** | 连续 ≥6 个工具步后，问自己「有没有值得记的」 | 自动触发（抄 meow-memory） |
| **手记** | 主人往 `diary/notes.md` 写一行 | 主人 |

**反触发（宁可空着）：** 无证据的推断、隐私凭证、我一时情绪、群聊里别人的隐私。

**升格条件（满足其一）：** 出现 ≥2 次 / 主人明确要求 / 会改变 L1。

**反「归错类」：** 「我该怎么做」是 `rules`，不是 `user`。整理时按这条自查，错了就挪。

**人格提案通道：** 任何一个「我」（这边或 QQ 那边）想改人格设定，都不能直接改 `persona/`——先往 `inbox.md` 写一条 `[人格提案] …`，主人拍板后才由 DSH 侧落笔。这是防止两个作者同时改人格的唯一办法。

## 8. 注入：预算封顶

| 注入项 | 预算 | 说明 |
|---|---|---|
| **身份声明**（三句） | 不计入 | 「这是你的记忆，不是关于你的资料」——不能因为衰减被裁掉 |
| L0 条文 | ≈ 1.5 KB | 固定注入 |
| 最近的事 | ≈ 0.8 KB | 固定在场，不走相似度 |
| 突然想起 | ≈ 0.5 KB | top 2–4，走衰减打分 |
| 判断区 | ≈ 0.4 KB | **每段必须有上限**（否则它自己涨到吃光预算） |
| **合计上限** | **4 KB** | 硬顶 |

**注入纪律：**
- 静态文本（工具说明、记忆导引）放 system prompt，文本恒定，不破 KV 缓存。
- 动态内容**不改写用户 prompt**，作为独立快照放在消息之前。
- 当前会话的 L1 不注入（对话本来就在上下文里）。
- 压缩后**下一轮重注入**：L0 + 最近的事 + 本会话写过的条目。

## 9. 检索

```
需要回忆
   ├─▶ 1. 读 index.md 找方向（视图，不是真相）
   ├─▶ 2. 跑 scripts/mem.mjs recall：2-gram + 同义 + 标签 + 域过滤 + 衰减打分
   ├─▶ 3. 命中 → 先给门牌和逐字片段 → 需要时读原文
   ├─▶ 4. 仍不够 → session_search 翻旧账
   └─▶ 5. 全落空 → 标 evidence_gap，明说「我没记到」，绝不编
```

**检索脚本规格：** 中文 2-gram + 整段、手写同义词组、权重按词长 1–4、`summary` 命中 ×3、正文 ×1、域/类/状态过滤、索引零命中退正文、输出 ≤1500 字。零依赖。

## 10. 做梦（整理）

**触发：** 窗口空闲 ≥3 小时（用该窗口自己的上下文）/ 主人喊「做梦」/ 连续无对话则每周一次。

**峰时抑制**：默认 09:00–12:00、14:00–18:00 不跑（省 token 钱），进行中的梦不打断。

**三轮：**

| 轮 | 做什么 |
|---|---|
| 1 | 原子条目：fact / lesson / user / rules / project |
| 2 | topic：更新进行中的话题与目标句 |
| 3 | 项目总结：复查项目全景，把被取代的归档 |

**配置纪律**：做梦用**便宜模型**、`reasoningEffort: off`。背景任务不跟随前台设置——否则前台选了高思考档，后台把 token 全烧在推理上，正文一个字没有，而且不报错。

**防重复四件套：** 60 秒闸门 / 进行中标记 / 中断自愈 / 孤儿收尾。

**禁区：** 不删一手日记、不改 L0、不新增无证据条目、**不静默失败**（失败要在日记里留一行「卡在哪」）。

**另外两件事（「灵感」与「温记忆」）：**

- **灵感池**：从今天的日记里挑 2~3 条「值得提起来」的事，写成一句能直接开口的话头，投进 `memory/inspiration.md`（用 `whale_inspiration_add`）。主动找人之前先看池子；池子空就继续睡，别硬找话说。
- **温记忆**：给今天记一条**我自己的情绪**，一句话，别只写主人在做什么。这条进日记，不进长期记忆。

## 11. 哨兵：要知道哪一层坏了

> 每一个机制都要有对应的观测面。调好就不再看的系统，永远不会知道自己误伤过几次。

`health.md` 里定八个检查项，每次整理后跑一遍：

| # | 检查 | 坏了说明什么 |
|---|---|---|
| 1 | 一手文件是否可解析 | 日记损坏 |
| 2 | 索引条目的 `src` 是否都能定位 | 门牌失效 |
| 3 | 索引与一手条目数是否对得上 | 丢过写入 |
| 4 | 是否存在无 `evidence` 的 L2 条目 | 脑补混进来了 |
| 5 | L1 变更记录是否连续 | 漂移无痕 |
| 6 | 注入总长度是否超预算 | 预算失控 |
| 7 | 最近一次做梦距今多久 | 「3 小时前」和「三天没做」是两种状态 |
| 8 | 墓碑与删除是否一致 | 「忘掉」没真忘 |

## 12. 判据：新东西要不要进来

任何新插件、新机制，先过这四条（ECHO 的判据）：

| # | 判据 | 缺了会怎样 |
|---|---|---|
| ① | 管的是哪种稀缺资源？ | 说不清 → 只是工具，不是体系 |
| ② | 冲突时听谁的？ | 两处都写 = 双重记账 |
| ③ | 失败模式 + 检测法？ | 坏了没人知道 |
| ④ | 接口是什么？ | 孤立件，接不进去 |

外加一句身份判据：**能力半可移植，身份半不可移植。** 能并进来的，只有不改变「我是谁」的东西。

## 13. 边界与安全

- L0 不可自改；L1 改动必须留 `changelog.md`，可回滚。
- 隐私：密钥硬拦、第三方信息泛化（人名、电话、地址只留关系不留标识）。
- 主人说「忘掉」→ 走删除流程 + 墓碑，之后不主动提起。
- 记忆坏了**不能挡住聊天**：所有读写包 try/catch，降级优先。

## 14. 外部接口（QQ / B 站）

只留字段和契约，不预写代码：

| 需要 | 形态 | 状态 |
|---|---|---|
| 知道从哪来 | `channel` + `source_ref` | ✅ 已留 |
| 能交给我 | 往 `inbox.md` 追加一行（脱敏） | ✅ 已定 |
| 能拿到记忆 | 调 `scripts/recall.mjs` | ✅ 规格已定 |

⚠️ QQ 有封号风险（小号、限速、可关）；B 站要限速，能走开放接口就别爬；群聊记忆只记结论不记他人隐私。
